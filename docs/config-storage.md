# 配置存储、迁移与缓存

配置继续使用 JSON，管理面板和后台任务通过原有 store 与设置接口读取同一份数据。公共配置和账号配置分开落盘，减少读取和保存时重复处理全部账号。

## 文件布局

以下路径相对于实例的 `data/` 目录；源码运行时为 `core/data/`。

| 路径 | 内容 |
| --- | --- |
| `accounts.json` | 账号列表和下一个账号编号 |
| `store.json` | 公共配置，包括系统、登录、通知和界面设置 |
| `account-configs/.format.json` | 逐账号配置格式版本，目前为 1 |
| `account-configs/<id>.json` | 一个账号的完整配置文档 |
| `store.json.<随机标识>.bak` | 自动拆分前的原始 `store.json` 备份 |

正常的数字账号编号直接作为文件名。其他历史编号经过可逆十六进制编码，避免路径穿越、Windows 保留名称及大小写冲突；账号编号本身不会改变。

神秘商人交易记录、资源预留等运行数据继续走各自原有路径；配置拆分不会迁移或合并它们。

## 自动迁移

只有主进程启动时会迁移。Worker 读取已有配置并接收主进程下发的快照，不会因启动而发起拆分或写回系统默认值。

1. 读取并校验旧 `store.json`。没有旧文件，或没有非空的 `accountConfigs` 时，跳过拆分，不创建空配置目录或迁移备份。
2. 检查各账号配置，复制一份原始文件作为 `.bak` 备份。
3. 在 `account-configs.migrating-<随机标识>/` 中逐个写入配置，读回核对，并写入格式标记。
4. 将整个临时目录重命名为 `account-configs/`，一次性发布已验证的配置集合。
5. 从公共 `store.json` 中移除旧账号配置集合，保存 `accountConfigStorageVersion: 1`。

新实例首次保存账号配置时才创建逐账号目录和格式标记，不生成旧数据备份。后续一个账号的配置保存只更新该账号文件；公共设置只更新 `store.json`。内容没有变化时跳过写盘。

已拆分后若 `store.json` 中仍残留账号配置集合（例如清理失败或旧版本写回），启动时以 `account-configs/` 为准，清理前会先将当时的 `store.json` 另存为 `.bak`。`account-configs/` 中无法识别的文件名（如手动复制出的 `1 - 副本.json`）会在日志中警告并跳过，不会被当作账号配置读取。

迁移过程中的临时目录不会被当作正式配置读取。发布前发生写入失败，原始 `store.json` 仍有效，下次启动可以重试。已发布后公共文件清理失败时，会报告错误；下次启动以已发布目录为准并重试清理，不会让残留的旧账号配置覆盖新设置。失败尝试留下的临时目录和备份会保留，确认正式配置与备份完整后可以停服清理。

## 缓存、保存与错误

- 账号列表首次读取后缓存在主进程内存中，新增、修改及删除在成功写盘后更新缓存。调用方得到独立快照，修改返回值不会影响缓存。
- 同一实例由主进程负责配置写入。缓存不使用文件监听器或后台定时器；手动编辑运行数据后应重启实例。宿主内部可调用 `models/store/accounts.loadAccounts()` 显式重新读取账号列表。
- 配置保存保持同步落盘，保存成功后才发布内存中的新值。失败会向原调用方抛出 `STORAGE_READ_FAILED`、`STORAGE_WRITE_FAILED` 或 `STORAGE_MIGRATION_FAILED`，接口不会将失败的保存报告为成功，也不会为失败的设置推进 revision 或下发 Worker。
- 配置文件存在但内容损坏、无法读取、拆分目录缺少格式标记或格式版本不支持时，会明确失败，保留原文件供修复，不会按空数据覆盖。
- `persist: false` 的账号快照继续用于 Worker 的内存同步，不落盘账号或界面设置。已知好友缓存仍按原有逻辑维护。

拆分后仍然是多个独立 JSON 文件，没有通用跨文件事务。保存账号配置与公共界面设置等组合操作，应分别确认结果；消费类操作继续复用原有专用安全链路。

## 备份与恢复

停服后备份整个 `data/` 目录或 Docker 数据卷，包括 `account-configs/` 和其他运行数据。自动生成的 `.bak` 只负责保留迁移前的公共配置文件，不能替代完整数据备份。

旧版本不认识逐账号配置格式。降级前应停服，把最新的逐账号配置合并为旧版格式，或整套恢复升级前的备份并接受备份后的修改丢失。只覆盖一个旧 `store.json` 不会使新版放弃已发布的 `account-configs/`，也不能用这种方式回退其他运行数据。
